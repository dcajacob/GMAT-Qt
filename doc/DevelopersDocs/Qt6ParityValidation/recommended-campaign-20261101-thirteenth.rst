Why reference restoration is admissible
---------------------------------------

Several original mappings named later production-source hashes, while the
retained runs used the exact mapped assertion sources. This review records the
actual frozen production versions. It does not rebind an old run to newer code.
Every original assertion source/hash, anchor, expected value, facet, scope,
reference path and post-execution normative-reference role remains unchanged.
Only the explicitly recorded reference versions may change.

Production C++ reference changes preserve their actual execution context,
including the older Yukon source used by the nonlinear case. They grant no new
core approval or newest-source equivalence. Arbitrary test-helper, expected-data,
application-data and normative-document reference changes are rejected.

The single special data reference is NasaReportOutputCases.json. Its actual
registered command must execute SubscriberToggle using that exact frozen file.
The selected record, including config/base/values/invalid cases and requirements,
and every noncase metadata field must be identical to the original mapped
version. Only other unexecuted records may differ. The exact unchanged driver
source must retain its keyed case-selection mechanism. Three clause-level
comparisons reuse one original unattended selected-case context; no assertion
or expected value is dropped.

Original collection admission requires sealed ledger audit/report/receipt/mapping
identities and a recorded receipt/hash pair or original raw-artifact seal. Only
original results.json executions are admitted. Frozen NASA authorities, snapshot
fingerprints, completed/unchanged execution, registered commands/cases,
executable identities, source/reference bytes, exact terminal/JUnit and every
original assertion remain mandatory. Passing visible checks require native
exposure. A missing binding is an explicit unqualified diagnostic; it cannot
supply accepted scope credit.
