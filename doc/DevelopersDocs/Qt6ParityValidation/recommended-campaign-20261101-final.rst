Bounded NASA GUI acceptance campaign: final handoff
===================================================

The recommended **217 recovery reviews and 37 local acceptance contracts are
finished**. This closes the bounded campaign selected in
``remaining-feasibility-20261101.rst``. Broader NASA qualification remains open.
The source-versioned union is **924/1,158 requirements (79.8%)** and
**1,816/2,367 historical scopes (76.7%)**. Every original source denominator,
remaining row, authority conflict and global qualification gate is retained.

Requirements are statements of intended capability from the available NASA
workbook. Historical scopes are operations from its 2012 requirements-to-test
matrix. They are separate populations; neither percentage measures the fraction
of all GUI widgets clicked or certifies scientific correctness. The current
private NASA corpus has not been obtained.

-----------------

158 complete source-versioned scopes accepted, 59 held for missing obligations.

missing proof or scope conflicts, not 59 newly demonstrated application defects.

bindings, receipt/binary identities, exact passing JUnit, complete mandatory
cohorts and explicit acceptance or rejection rationale. No held row receives

Repairs and core scrutiny
--------------------------

The recommended campaign changed four core paths: InternalOptimizer.cpp and
Optimize.cpp for correctly timed VF13ad progress reporting; MessageWindow.cpp
for Precision metadata; SolarPowerSystem.cpp for five dimensionless coefficient
labels. Optimize was already changed before this campaign. Three added paths
bring the HEAD-versus-worktree inventory from 97 to **100 changed core files**.
All 100 remain pending independent technical/scientific scrutiny.

``final-core-scrutiny.json`` names every current core file with HEAD, working and
patch hashes, observed purpose and campaign provenance. The exact incremental
VF13ad, MessageWindow and SolarPowerSystem patches/reviews remain beside it.
Protected TimeSystemConverter.cpp and MinQP.cpp identities are unchanged in this
campaign. Matching source hashes and focused tests do not approve every core
hunk, physical domain, ABI, provider, ownership or concurrent-use behavior.

The Qt repairs include retiring superseded orbit input assignments on Apply,
and converting native sensor-mask radians at the Qt receiver boundary. Original
strict result/source assertions and directly affected regressions are retained.
No production/core/assertion source changed during final consolidation.

``final-failure-dispositions.json`` preserves all eight failed GUI development
attempts found in this campaign, their relocated raw logs/JUnit and final passing
receipts. It distinguishes the stale nominal reporting and mixed-input Apply
product defects from display startup and fixture corrections. It also records
the Precision, solar metadata and sensor-mask targeted before/after checks.
The documentation auditor's development selector/count mistake and the final
auditor's initial misclassification of library symlinks as copies are recorded.
All retained library links target the installed application; actual copied or
unexpected libraries are rejected.
The earlier 24 baseline failures and their inspected later passes remain in
``retained-baseline-failure-dispositions.json`` at their original source versions.
Their later passing result, log and JUnit artifacts are rechecked at final freeze;
they are not upgraded to a single current-binary regression.

A separately discovered indexed Transmitter.FrequencyBiasSigma getter appears
to return the bias vector. This remains an **unverified core candidate**: no
runtime reproduction or fix is claimed; the Qt whole-vector getter is distinct.
It needs a separate targeted engine review and receives no coverage credit.

Remaining scope and limits
---------------------------

``campaign-gaps.json`` retains **234 requirement and 551 historical gaps**, each
with its original identity, source text, feasibility classification and closure
gate, plus the applicable held campaign decision. This includes all 59 held
recovery obligations. Optional MATLAB/FMINCON, MarsGRAM/DE405, absent MSISE86,
C-client, specialized comparators, arbitrary frame/state/science domains,
obsolete platforms, missing private procedures/body fixtures and disputed legacy
behavior have not been implemented or silently retired to increase a percentage.

The handoff carries every original global gate, original nine-gate routing and
source-conflict disposition. Native host input/portals, physical GPU lifecycle,
prepared visibility workflows, finite stress/capacity, remaining supported
unexecuted tutorials, independent scientific truth and current NASA authority
remain separate qualification work. A completely rebuilt release artifact and
one deduplicated full replay are still required before a whole-current-build
release claim. Historical receipts are not attributed to today's complete binary.

Full-current-build qualification, full-NASA qualification and technical core
approval are all explicitly false. Completing this bounded campaign does not
close those gates or claim 100 percent of either original source population.

Verification and reuse
-----------------------

The final consolidation launches no GUI scenario or mission. Eight new admission
guards and the existing 44 recovery support contracts pass. Their synthetic
fixtures add no NASA credit. The read-only final handoff audit rechecks every
recovery family, all five local qualification inputs, the exact 254-row union,
every remaining original row, protected inputs and the current core inventory.
It validates receipts and source versions rather than rerunning passing GUI cases.

From the repository root, reuse the complete final evidence with::

   python3 src/qtgui/tests/AuditAcceptanceCampaignHandoff.py \
     --evidence-root build/nasa-coverage/recommended-campaign-20261101 \
     --output /tmp/gmat-campaign-handoff-check.json

Run the documentary audit alone with::

   python3 src/qtgui/tests/AuditAllInputDocumentation.py \
     --evidence-root build/nasa-coverage/recommended-campaign-20261101 \
     --output /tmp/gmat-input-documentation-check.json

Run the affected admission guards with::

   python3 -m unittest discover -s src/qtgui/tests \
     -p DocumentationAcceptanceTests.py -v
   python3 -m unittest discover -s src/qtgui/tests \
     -p AcceptanceRecoveryTests.py -v

To watch the new physical-input case yourself on the current build, choose a
fresh output directory and run::

   python3 src/qtgui/tests/RunAcceptance.py --build-dir build/linux-gui \
     --filter '^QtGui[.]NativeNasaUnitInputs$' \
     --nasa-review src/qtgui/tests/NasaUnitInputTraceability.json \
     --visible --start-minimized --pause-ms 600 --max-checkpoints 5000 \
     --max-screenshots 0 --output /tmp/gmat-units-watch

To watch the new reporting cases, choose another fresh output directory::

   python3 src/qtgui/tests/RunAcceptance.py --build-dir build/linux-gui \
     --filter '^QtGui[.]NativeNasaVF13adProgress(Forward|Central)$' \
     --nasa-review src/qtgui/tests/NasaVf13adProgressTraceability.json \
     --visible --start-minimized --max-screenshots 0 \
     --output /tmp/gmat-progress-watch

Restore the initially minimized, resizable test desktop when ready. It is not
fullscreen. These commands are provided for deliberate user replay; they were
not executed again for this handoff. The same underlying CTest cases remain
available unattended. Current-source replays produce new receipts and cannot
replace retained source-versioned proofs by relabeling them.

The campaign directory retains small raw/configuration/text/CSV proof and frozen
text-source archives. No passing screenshots or runtime/binary copies were added.
Existing sealed baselines and the original GMAT checkout remain preserved.
