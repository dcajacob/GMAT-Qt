New reusable catalogue
------------------------

``src/qtgui/tests/AcceptanceCatalog.py`` provides:

* Typed, lossless metadata for earliest/latest supported build dates, requirement
  links, author, truth-file identity/literal truth, tolerance policy, comparator,
  user extensions, comments, creation date and platform dependencies.
* Inclusive build-date eligibility and exact dependency labels. Unknown dates,
  authors/platforms and other missing legacy metadata stay explicit. A Qt backend
  such as xcb is not substituted for an operating-system identity.
* Failed-test groups for Acceptance/System/Validation and recorded platform,
  requirement-set queries with exact source keys, and no-test queries distinct
  from unexecuted, skipped, failed and unverified evidence.
* Optional summary-only exports and explicit counts/names for tests run, passed,
  failed, reused and execution-unproven, plus failed requirement keys/names.
  Reused outcomes and disabled registrations do not inflate tests actually run.

Metadata tolerances are descriptive and never override existing fixture
assertions. Existing tests without populated metadata are not assigned invented
authors, dates, classifications or truth. Supporting the metadata contract does
not mean all legacy metadata has been populated.

The new CTest registration ``QtAcceptance.CatalogueContracts`` passed thirteen
independent contract tests, including real CLI export/query calls, Unicode
round trips, inclusive date boundaries, all three failed-test classifications,
duplicate source-ID preservation, exact mixed-outcome summaries and rejection
of invalid/nonfinite metadata, invalid reuse and unknown/malformed records.

applicability with the same mandatory source-bound passing-proof checks as GUI

``NasaHarnessTraceability.json`` without editing the historical GUI manifest.

``RunHarnessAcceptance.py`` invokes only the explicitly reviewed backend CTest
registrations, records actual command/result/JUnit/log/interpreter/platform and
before/after source identities, and evaluates the exact emitted NASA_CHECK
records. It retains small matching text-source inputs for later reuse, without
copying interpreter/runtime binaries or the authority workbook. The first
catalogue run qualified all 21 declared rows; no GMAT GUI or engine case executed.

The initial source archive was retained after execution only while every byte
still matched the recorded before/after identities. It is not described as an

the reviewed manifest is the unchanged recorded input, every required source

declared runtime proofs still qualify. Pending/duplicate/partial or unrelated
GUI rows cannot enter via a backend qualification.

Use and remaining work
-----------------------

The new catalogue contract is included in ordinary CTest runs. To execute only
that new backend registration::

   ctest --test-dir build/linux-gui -C Release \
     -R '^QtAcceptance[.]CatalogueContracts$' --output-on-failure

To create a new source-bound backend receipt, choose a new output directory::

   python3 src/qtgui/tests/RunHarnessAcceptance.py \
     --build-dir build/linux-gui --output /tmp/gmat-catalogue-acceptance

To query an existing receipt without running tests::

   python3 src/qtgui/tests/AcceptanceCatalog.py \
     --receipt PATH/results.json --nasa-report PATH/nasa-requirements.json \
     --query summary --output /tmp/gmat-summary.json

Other queries are ``failed``, ``no-tests`` and ``requirements`` with repeated
``--requirement`` source keys. ``--metadata`` supplies the optional typed registry;
``--build-date`` and ``--platform`` filter metadata eligibility without inventing
the identity of old executions.

Continue the 127 remaining recovery audits and seventeen missing obligations, then
the six comparator/HTML, six solver-report and four unit/documentation contracts.
The goal stays active. No core or production GUI source changed, existing GUI
scenarios were not replayed, no window opened and no passing screenshots or
runtime/binary snapshots were created. Existing scientific/ABI review and
current-build/physical-host/NASA-baseline gates remain open. Future new GUI cases
retain initially minimized, resizable, non-fullscreen windows.
