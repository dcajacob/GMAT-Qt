Actual documentation repair
---------------------------

Sixty-seven missing Units entries were added to 20 shipped command-reference
pages. These distinguish object names, selectors and logical controls from
physical quantities. Achieve desired values/tolerances inherit goal units;
Vary guesses, bounds, perturbation, maximum step and additive scale inherit
control units. The existing nondimensionalization equation xn=m(xd+a) establishes
reciprocal control units for the multiplicative factor. Propagate stop goals
and tolerances inherit the selected stopping parameter's units, including
degrees for true anomaly and seconds for ElapsedSecs. Expression and loop
arguments retain their declared/selected numerical scales.

Every original source byte is recoverable by removing only the recorded Units
insertions. No field definition, condition, example, default or behavior is
rewritten. The common Qt input guide also explains these command conventions.
The field-table inventory now has 766 GUI-tagged entries with Units metadata
and two without, both in the inactive Command_Template.xml. That is a document
metadata count, not proof of complete active-input coverage.

DocBook schema validation and the full HTML build pass. All 67 new descriptions
were checked inside their own generated field-table rows. Only the 20 changed
existing topic pages and the existing single-page HTML guide were updated in
the offline application help. No image was copied by the deployment step.

What the new census actually measures
-------------------------------------

The probe initializes the existing runtime and uses the same resourceDraft,
resourceProperties and ResourceEditor helpers as the GUI. It measures metadata,
not user delivery, native exposure, numerical correctness or scientific truth.
No mission is executed. Every type is processed separately; output/log and
selected source/executable identities are retained. Results are compressed losslessly.
Full loaded-library/source provenance still needs sealing for final qualification.

The 84 distinct processes measure 1,085 default editable widgets and 324
single-selector variations. Across default and successfully measured variants,
there are 987 distinct type/field/unit records. Fourteen synthetic setter
combinations were rejected and remain explicit: twelve unsupported solver
ReportStyle choices and two ephemeris settings read-only in the default format.
These are not fourteen newly failed GUI acceptance cases; their actual
conditional UI routes have not been exercised by this probe.

A conservative owner-specific field-name crosswalk finds unit-table candidates
for 865 records and no exact binding for 122. A candidate match still needs
semantic review, aliases and dependent-unit narratives. The 987 records include
790 blank native unit strings. Blank is never treated as dimensionless. Five
SolarPowerSystem coefficient strings literally report kW?; their source marks
those native units TBD. Such metadata is not used to guess a physical unit.

The source inventory also records 296 input-construction sites in all 80 C++
files compiled into the frontend, including dynamic widget templates and
standard Qt input/file/color dialogs. These sites are templates, not 296 complete
or individually exposed input fields. Their documentation bindings remain open.

The runtime catalog additionally records 14 propagator, 22 axes, 8 attitude,
8 physical-model, 4 atmosphere and 52 command factory types. Those nested modes,
configured built-ins, command/expression inputs, narrative-only fields and
multi-selector unit dependencies still require reconciliation. A one-selector
sweep is not a proof of every conditional combination.

change adds the new metadata executable target. No prior GUI assertion or case

duplicate process, missing resource type, changed output identity and an
