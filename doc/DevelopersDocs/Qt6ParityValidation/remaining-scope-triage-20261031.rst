Release gate: prove the artifact once
--------------------------------------

**RELEASE** comes after the selected core/desktop work and any confirmed defects.
Pin the source revision plus dirty delta, toolchain, dependencies, plugins,
startup/data and build/install commands. Build and launch the actual installed
artifact in an isolated location. Verify the representative document/resource
edit, Save/reopen, execution/output and normal-exit routes from that installation.
Source and binary hashes alone do not prove how the artifact was built.

Review source-plugin rebuild requirements and changed object layouts. An
unchanged proprietary provider binary does not establish compatibility with a
changed spacecraft/interpolator layout. A trustworthy claim for changed numerical
paths requires appropriate reviewer disposition; a bounded GUI developer handoff
must continue to state the absence of scientific approval.

Continue to reuse unaffected passing evidence during development. If the release
requires a full final-binary regression claim, run the active catalogue once
at freeze, separating native, headless and support routes and the twelve disabled
hypotheses. Do not replay it after documentation-only work or call a mixed-version
union a final-build pass. Estimate 1-2 engineer-days to prepare the controlled
artifact receipt; build/run duration depends on the selected release scope.
