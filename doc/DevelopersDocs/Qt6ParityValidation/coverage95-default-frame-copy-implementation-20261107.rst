Editable copies of built-in coordinate systems
==============================================

Qt now offers Copy coordinate system in the Edit menu and on a built-in frame's context menu. This explicit path prepares an unregistered, editable user-frame draft from the original native frame and its independently cloned axes, retaining the origin, axes type and writable axes settings. Built-in protection and modification flags are changed only on the detached value. A scoped native configuration export supplies the otherwise absent Create declaration and effective defaults; authored resources continue to use source copying. Preview and commit share preparation and the existing name/settings/history/rebuild transaction. The ordinary Clone restrictions and separate propagator policy remain intact. Compilation only; default-body/calculated-point and remaining broad resource-copy cases stay open, with no row or verification credit.

Owning-source findings and implementation
------------------------------------------

The original worksheet's any-object copy requirement and the shipped guide's default-frame Clone restriction are both retained. The additional IncludeBuiltInFrames policy is reachable through an explicitly named Copy coordinate system action, using the existing copy editor, name validation, synchronized-source guard, unapplied-panel guard and candidate transaction. Context actions expose this additional route for default frames; the Edit action accepts a selected coordinate system. Native and IncludePropagators enum values and original ordinary-action behavior remain. Propagator eligibility now tests its specific additional policy, preventing the frame policy from accidentally admitting a propagator.

resourceCloneDraft uses the native Clone before renaming. CoordinateSystem's native copy constructor independently clones its owned axes. For the explicit frame-copy policy only, the detached frame loses its built-in flag and SetModifyFlag(true) enables modification on the frame and its axes; the axes' built-in flag and diagnostic coordinate-system owner name are also updated. The live configured default receives none of these operations. Both preview and final commit use this preparation, rather than preparing an editable source candidate with a still-protected editor draft. Solar-system objects are not duplicated and live frame/session caches are not transferred as a public resource operation.

Built-in frames are synthesized by Moderator rather than an authored Create declaration. For those frames only, cloneResourceSource seeds its extraction input with a detached native OBJECT_EXPORT under ObjectScriptExportScope. The existing scoped serializer includes defaults, native ordering, owned axes, exact string literals and sufficient Real precision without changing process settings or source-object flags. The synthesized declaration/assignments are renamed with the existing assignment-owner rule. Main or captured-include configuration remains after this seed, preserving authored source overrides. Ordinary authored frames/resources retain their existing source extraction path and camera/default/reference handling.

The synthetic prefix is extraction input only. It is not added to the original document or fed back as a replacement full mission. Boundary mapping explicitly subtracts the prefix before looking up captured block ranges, and maps the final boundary back to one unique main-source statement or permitted mission-only include anchor. Resource-only scripts retain EOF insertion. The native seed is used only for built-in frames; class/provider configurations without native serializable declarations are not implicitly admitted. Mixed configuration/mission include and included marked-array ordering guards remain.

Source inspection identified materially different default-body semantics: CelestialBody::SetUserDefined(true) changes supported DE ephemeris selections to SPICE. CalculatedPoint built-in behavior is also class-specific. The frame-copy implementation therefore does not apply a generic unprotect-and-rename recipe to bodies, calculated points or SolarSystem. Their original broad requirement scope remains open for an actual semantics-preserving implementation or supported specification resolution. Current Moderator source creates four user-facing protected defaults: EarthMJ2000Eq, EarthMJ2000Ec, EarthFixed and EarthICRF. Their functional/scientific equivalence after copying has not been run in this implementation phase.

It does not close the original any-object Clone row, add default-body or built-in calculated-point copies, change native standard Clone policy, or establish complete provider/class-specific configuration fidelity. Mixed configuration/mission includes, included marked array initializers, dependency/order/freshness cases, all other remaining Resource Tree and function/Save/body/frame/kernel/ephemeris scopes remain open.
