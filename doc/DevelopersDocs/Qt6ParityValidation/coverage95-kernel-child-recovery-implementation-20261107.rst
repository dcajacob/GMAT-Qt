Native meta-kernel child recovery and alias unload
==================================================

UnloadKernel now resolves actual native loaded names, admitting recognized filesystem aliases and meta-kernel children even without requested-name map entries. Failed-unload reconstruction restores each surviving root's observed ordered child selection before furnishing later roots, omitting the requested last child occurrence as well as preserving earlier child removals. It prunes replay-only children in reverse order, preserves duplicates and retained later occurrences, compares complete file/type/source sequences and checks the pre-root table prefix. A failed or incompatible replay triggers attempted retirement of that new root, with explicit retirement errors. Root order, membership reconciliation, revision invalidation and failure statuses remain. Compilation only; complete ownership, file-content/pool-value lifetimes and original scientific scope stay open, with no row or verification credit.

Owning-source findings and implementation
------------------------------------------

The configured CMake CSPICE_DIR points to the dependency whose keeper.c was inspected and retained under dependency-preimages, with a SHA-256 record. That source appends a direct root and then its children, rejects recursive meta-kernel loading, removes the last matching filename and rebuilds remaining text/binary entries in table order. This supplies the implementation basis for processing one root segment at a time. It is a configured dependency source inspection, not proof that every platform/library build behaves identically, and no toolkit routine or example was executed.

The public native contracts also describe the last-furnish unload operation and provide filename/type/source metadata. Primary documentation: https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/unload_c.html and https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/kdata_c.html. ReadKeeperEntries now retains the native kind as well as filename/source. Existing grow-and-retry buffers, native-capacity checks and error/reset handling remain. All added entry/comparison/pruning helpers are private to SpiceInterface.cpp; there are no native public/protected signature, instance-layout, virtual-slot or parameter-ID changes.

The previous UnloadKernel admission searched only loadedKernels. A native/meta child or alternate loaded path could be recognized by IsLoaded yet rejected by UnloadKernel. Admission now uses the same native resolver as loaded-state/path discovery and validates that the selected native filename occurs in the captured table before mutation. This resolves a global native unload request; it does not acquire or release a per-resource ownership lease, and cannot recognize an arbitrary vanished alias whose filesystem identity is no longer available.

For failure reconstruction, a directly requested root is omitted with its children. When the last requested occurrence is a meta child, the containing root is replayed with that occurrence omitted from its wanted child sequence. Each other root's wanted sequence contains exactly the surviving pre-failure entries, including repeats and previously removed children. The current native prefix is captured before each furnish. Fresh meta-kernel expansion is reconciled before later roots are loaded, so later occurrences of the same filenames are not accidentally targeted by cleanup. Requested-name reconciliation and the original unload failure result remain after reconstruction.

RestoreKeeperChildren matches the original ordered file/type/source subsequence, retaining counts and parent names. Replay-only entries must belong to the current root. Before any pruning, a reverse scan proves that removing each unwanted filename cannot remove a retained later occurrence instead. It then unloads extras from the end and checks the complete remaining prefix plus wanted segment. Missing, reordered, wrong-kind, wrong-parent or ambiguous duplicate selections fail this comparison rather than being reported as an exact restoration. Earlier child-only removals from an unchanged meta-kernel are therefore represented explicitly in reconstruction rather than silently undone by re-furnishing the parent.

A failed furnish or unsuccessful reconciliation invokes DropReplayedRoot. Retirement requires the previous prefix still to match and the next admitted entry to identify this new direct root, avoiding removal of an older matching root when furnish failed before admission. It unloads the new root and checks that the previous prefix remains. Native/query/retirement errors are logged and reset where appropriate; retirement or prefix restoration can itself fail and remains a reported incomplete state. Revision notification precedes every raw child/root mutation. No synthetic meta-files, copied input kernels or new path spellings are introduced.

Limits
------

This implements native alias/child unload admission and reconciliation of recoverable meta child selections at source level. It does not preserve previous bytes of edited/unavailable files, programmatically supplied pool values, arbitrary low-level loaders, changing-directory/in-place-replacement lifetimes, per-resource kernel ownership/leases, concurrent native mutations or error propagation through every caller. Changed metadata can make the prior ordered selection impossible to reproduce; root retirement itself can fail. Such cases remain failures rather than successful exact restoration. Matching filename/type/source records do not prove numerical identity or scientific validity. Full original resource-copy, body/frame/kernel, ephemeris and function/solver scopes remain open. No original requirements/text/fingerprints/fixtures/assertions/tolerances/dispositions/gates/denominator or numerical equations change. No tests, native/model/helper/parser/GUI/kernel/API/mission/scientific execution, acceptance auditors/readers/seals or evidence admission occurred.
