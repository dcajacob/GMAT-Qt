Production route and exact review scope
--------------------------------------

Matrix and MAT-file API entry points. The caller waits synchronously while the
existing UI interpreter hook services Qt callbacks. Exceptions return to the
owning caller;off-owner and reentrant requests are explicitly rejected. The real
GMAT Optimize/ExternalOptimizer state machine and actual branch commands still
evaluate the objective and constraints on Qt's thread. No mock optimizer,solver
substitution or emulated MATLAB result is used.

bounded newline/JSON framing,request identity checks and an evaluation-only
operation. It cannot submit a MATLAB-to-GMAT script. It validates finite controls
and uses the existing callback registration. The native Optimize callback now
checks the complete registered input vector before use,resets its executing flag
on exception and unregisters its own identity on completion/destruction. New
nonvirtual GmatInterface methods provide an untruncated std::string result path
and identity-checked unregister. The legacy char API remains and explicitly rejects
results beyond its1024-byte capacity before copying. No existing core class gains a data member or virtual slot
from these changes. QtInterpreter gains a private service member and an
override of the existing server-start hook;its frontend layout changes.
