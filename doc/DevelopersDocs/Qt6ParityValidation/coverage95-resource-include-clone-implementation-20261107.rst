Resource cloning from captured included configuration
=====================================================

Qt resource copying now extracts declarations and owner assignments from the logical mission source read during the most recent successful Qt Build, including nested includes and main-document overrides. The native interpreter offers an optional thread-local scoped capture; ordinary interpretation without an observer retains its existing behavior. The Qt wrapper stages and publishes a text-keyed snapshot only after successful interpretation, function validation and path restoration. Clone extraction uses that snapshot while insertion edits only the current document. Main-source and mission-only-include boundaries are mapped explicitly; combined configuration/mission includes and included marked array initializers reject rather than move expressions across dependencies. Original clone policies, references, defaults, camera metadata and commit/rollback paths remain. Compilation only; whole-row implementation and acceptance remain open.

Owning-source findings and implementation
------------------------------------------

The previous helper searched only the main editor source. Native resources declared in includes appeared in the Resource Tree but failed the declaration lookup, and a main-declared resource configured through includes could lose those assignments in its copy. Reading files again when opening the copy editor would observe a potentially different revision from the successfully configured model. ScriptSourceCapture now observes ReadFirstBlock header text and each original ReadScript logical block before evaluation and include recursion. It skips function-body reads and delayed-block replay, records top-level include anchors across nested reads, and owns text only. An inactive observer does not accumulate data. Scope destruction restores the previous observer on success or exception. No fields or virtual slots are added to existing native classes; the new exported helper is defined in the existing interpreter translation unit.

qtInterpretScript clears the old snapshot before a new interpretation, captures only the native mission read, converts consumed logical blocks into a joined QString source with block offsets and root anchors, and ends capture before function-body validation. It stages all allocations before cache publication. Publication follows successful native interpretation, function validation and the existing FOV path restoration. A failed interpretation or validation leaves no published snapshot. The getter returns a copy only for the exact main input text. Existing normal Build, candidate rebuild, folder interpretation/restoration and rollback callers all use this wrapper. No owning model pointers are stored in the cache. This is an observation of Build input, not a filesystem change watcher or a claim of external-file freshness during later interpreter calls.

The clone helper retains the original source path for scripts without includes. For scripts with includes it requires the matching successful snapshot and extracts all pre-mission declarations/owner assignments from the consumed logical source, preserving assignment-owner-only renaming, references, expression spelling in logical blocks, native property-alias matching and selected default materialization. Include directives are not copied into the resource block or executed as an expanded replacement document. Native continuation handling may normalize logical blocks; this is not a byte-for-byte copy of external file formatting. The original main document and included files are retained, with the new declaration/settings inserted through the existing source/history transaction. External files are never copied or rewritten by the extraction helper.

Insertion coordinates are computed in the original main document, independently of expanded-source offsets. A boundary in the main document must match one unique normalized statement. A boundary in an include is traced to one unique top-level include statement. Insertion before a mission-only include is permitted, including nested mission-only includes and an otherwise empty BeginMissionSequence. If that same include tree contains effective resource configuration before the mission, the helper rejects: moving the copied expressions before such configuration could change their inputs. A mixed configuration/mission include therefore remains an explicit unresolved implementation subcase. EOF remains a valid insertion point for a resource-only script without a mission.

Included marked array initializers are detected in the captured source and reject when the corresponding initializer is absent from the main document; the helper does not silently omit them or move them past commands in the include. Existing main-source array block copying remains at the original evaluation point. Camera metadata continues to use the main source, matching the current Qt Build camera-loading policy. Native standard-action built-in/propagator protections, the separate propagator copy action, formation consent, unregistered draft editing, alias/default preservation, source synchronization, candidate interpretation, undo/history and rollback policies remain unchanged. The original 33-category inventory and original assertions remain the scope authority.
