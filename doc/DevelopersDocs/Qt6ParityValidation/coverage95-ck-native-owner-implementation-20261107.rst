Native CK handle transitions and clock value ownership
======================================================

Native CK switching now refreshes its owned filename pointer and obtains a checked writable DAF handle when appending to an existing CK. Handle/open state is published only after successful native opening. Close errors retain handle ownership and propagate; explicit AbortKernel and guarded destruction release failed sessions without retrying buffered output after failure. CK value copies deep-copy segment/clock values while starting without a borrowed native or C stream handle; assignment stages storage before destination finalization and swaps completed values. Clock copies now retain their UTC identifier/time-system data. Segment buffers, native scratch arrays and metadata streams/text units use staged or scoped ownership. The subscriber destructor catches finalization errors and retains uncertain clock files. Compilation only; subscriber assignment, shared leases and full original scientific scope remain open, with no row or verification credit.

Owning-source findings and implementation
------------------------------------------

The owning source showed SetCKFile replacing kernelFileName without refreshing kernelNameSPICE, leaving the inherited native filename pointer tied to an old string allocation. OpenFileForWriting obtained a handle only when the file did not exist, then marked fileOpen true even for an existing file without opening it. Switching now stages the filename, refreshes the pointer, clears the stale handle and reopens the session state. New outputs still use CKOPN. Existing files must identify as DAF/CK and are opened with DAFOPW into a temporary handle before publishing owned open state. Constructor overwrite/rename policy is retained; switched-to existing CKs append.

NAIF documents DAFOPW write-open behavior and rejection of an already-open file. Primary contract: https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dafopw_c.html. CKCLS documents an empty-file error: https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ckcls_c.html. The configured dependency's retained ckcls.c confirms that NOSEGMENTSFOUND returns before DAFCLS. FinalizeKernel therefore no longer marks the handle closed before checking native success or suppresses the error as a successful finalization. AbortKernel explicitly closes the owned DAF without emitting pending data and then clears session storage. No original numerical equations, interpolation choices, quaternion mapping or epoch conversion are changed.

SpiceAttitudeKernelWriter copy construction now copies all four segment collections and metadata/temp-path values, owns a private cloned clock and starts with fileOpen false, no native handle and no C FILE stream. It does not finalize, write, reopen or borrow the source output while being copied. Assignment constructs that completed value first, finalizes the destination's previous output and then swaps owned value fields without further allocation. Both objects refresh native string pointers after the swap. Old closed resources retire through the temporary's destructor. I/O failure while finalizing remains a reported failure, not an atomic rollback of earlier file output.

SpiceSCClockKernelWriter initializes its time-system value, copies the clock UTC identifier as well as partition/coefficient data and uses staged copy/swap assignment. Its native filename pointer is rebound to its own string after both swaps. A1Mjd value copy/assignment source was inspected; the date values swapped here contain numeric storage and do not invoke native time conversion. File/clock value copying does not copy external file contents, preserve arbitrary active I/O sessions or allocate a new user output namespace.

The low-level CK destructor catches and reports finalization failures, attempts AbortKernel on failure and deletes its owned clock object. The prior shallow clock pointer could not safely be deleted and leaked. The higher AttitudeWriterCK destructor now catches its explicit FinalizeCKFile failures, guards diagnostics and preserves clock files when finalization or the initial unload failed. Its existing live cleanup interface remains through low-level destruction. This caller change was promoted from the already captured reference preimage before edits; no preimage was replayed. Subscriber-level operator= is unchanged and remains a concrete follow-up.

StoreSegment validates matching nonempty epoch/quaternion input, native index capacity, nonnull epochs and four-element attitudes before publication. It prepares all four replacement collections before swapping them into the writer. CK write scratch buffers now use vectors, including error paths that previously leaked allocations during tick conversion or subsequent native calls; the unused fake-rate buffer is removed. The CK type-5 call and existing numeric transformations are unchanged. Metadata uses a scoped C stream with checked open/write/flush/close, a bounded filename buffer and a scoped native text unit so comment failures cannot abandon the opened unit. Initial probe FILE pointers are cleared after close.

No fields or virtual slots are added to either native class. AbortKernel is a new nonvirtual native API; private swap helpers are also nonvirtual. Native consumers need the matching rebuilt core for the new API. No original parameter IDs, requirements, fixtures, assertions, tolerances, dispositions or gates change. Kernel pool leases, file-path conflicts across all constructors, source-file content snapshots, clock coefficient/partition assembly and complete all-writer copy/session semantics remain separate unresolved implementation work.
