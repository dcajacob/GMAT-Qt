Failed-unload recovery in observed kernel-root order
====================================================

Native failed-unload recovery now snapshots KEEPER's actual ordered file/source entries before mutation and replays the remaining directly furnished roots in that order. Recovery bypasses LoadKernel's normal deduplication so repeated native furnish operations retain their order, and includes observed roots absent from the wrapper's requested-name map. Only the last matching direct-root operation is omitted. Ambiguous child-only history does not trigger a guessed global reconstruction. Successful and failed unloads reconcile requested-file bookkeeping with actual native membership. An unload error returns false; batch unload attempts all entries and aggregates failures. Filename/source outputs grow before exposing truncated paths. Compilation only; complete meta-kernel/ownership/recovery/scientific scope remains open, with no row or verification credit.

Owning-source findings and implementation
------------------------------------------

The prior recovery iterated loadedKernels, a std::map keyed by requested filename. That sorts recovery alphabetically, omits roots furnished outside the wrapper and routes replay through a shortcut that skips already-loaded files. NAIF documents that later loads have higher priority for competing data and that each furnish creates a KEEPER entry, including repeats. These are reasons to preserve observed furnish order rather than map order. Primary source: https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/kernel.html. Documentation is not runtime evidence for this implementation.

ReadKeeperEntries is a private translation-unit helper shared by recovery and GetLoadedKernelNames. It obtains ordered ALL or selected-kind entries with file/source metadata, grows both buffers when an output exactly fills capacity, checks native integer capacity and reports/reset native errors. KEEPER source is empty for direct furnish roots and identifies a meta-kernel for a child. The native filename-membership query is also factored into a private helper; no native class fields, public/protected signatures, virtual slots or parameter IDs change. Primary API contract: https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/kdata_c.html.

UnloadKernel captures native entries and requested-file metadata before calling unload_c. It finds the last entry with the actual native filename. If that entry is a direct root and native unload fails, recovery clears the failed pool and furnishes each remaining observed direct root in original table order, omitting that occurrence only. It calls furnsh_c directly rather than normal LoadKernel so repeated roots are not coalesced; meta children are supplied by their roots rather than separately replayed as new direct loads. Revision notification precedes reset/replay mutations, including failed loads. Individual replay errors are logged and reset so the existing best-effort recovery can attempt later roots.

If the last matching native entry is a meta child, or no matching root can be established, failure recovery retains the native failure state and reports the missing direct-root history instead of clearing all kernels and guessing a parent removal. Native unload semantics erase the last matching furnish; meta-root removal also removes children, and text/meta unloads rebuild the text pool. Primary contract: https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/unload_c.html. This branch is an explicit incomplete ownership/recovery subcase, not a successful reconstruction.

After native success or the supported failure-replay path, requested-file bookkeeping is rebuilt from original requests whose resolved native filename is actually still loaded. This removes stale metadata and retains a filename still loaded through another furnish. A failed unload no longer falls through to successful completion after warnings: it returns false, and UnloadKernels continues all requested calls while combining their statuses. Existing callers that ignore these return values still need their own lifecycle/error review. Unload-by-unregistered-alias or child remains governed by the existing requested-name admission; this packet does not invent new ownership leases.

This replay preserves observed direct-root operation order, not arbitrary earlier file bytes, manually supplied pool values, edited meta-kernel child sets or prior individually removed children. Re-furnishing a meta-kernel reads its current child selection; partial load failure, changed/unavailable files or earlier child-only unloads can prevent exact effective-table restoration. Primary furnish semantics: https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/furnsh_c.html. Those remain explicit implementation gaps. The failure status is retained even if remaining readable roots reload successfully; no scientific-validity claim follows from recovery.

The same source review retained default-copy semantics in default-copy-followup-source-review.json. User-defined conversion and DE target lookup are not identity-neutral, built-in barycenter state is not the user-point mass sum, and existing whole-object initialization syntax does not supply a general default-body copy. No native body/point science or policy was changed as a substitute. The original full Resource Tree copy requirement remains open.
