Complete original conjunctions
-------------------------------

Some retained mappings deliberately require complementary tests from separate
original builds. ``AuditAcceptanceRecovery.py`` now accepts an explicit
``claim_bindings`` plan for those collections. It still loads the exact original
mapping, retains every mapped claim, and verifies each claim's original source,
references, registered command, executable identity, snapshot, complete passing
test log/JUnit and emitted proof. Each logical cohort must bind every mandatory
test to an execution declared in that original version's collection. Actual
receipt modes must be visible/headless, and each visible claim must have native
exposure. Missing tests, changed sources, missing terminal assertions, absent
exposure, wrong modes and receipts outside that collection reject recovery.

Complementary builds are explicitly recorded separately for every proof. They
are not presented as a single build or used to discard older mandatory claims.
This extends the audit's supported receipt structure; it does not relax the
proof verifier or any existing GUI assertion. The affected support registration
``QtAcceptance.EvidenceRecovery`` passed twenty tests: the original thirteen
recovery and three runner contracts, plus four new composed-binding contracts.
These support-test counts themselves grant no NASA coverage credit.

Every previously accepted recovery report was statically rechecked with the
updated verifier. No old GUI scenario was rerun. The original sealed receipts,
mappings, source snapshots and the separate catalogue/comparator qualifications
remain unchanged.

Remaining-claim preflight and gaps
-----------------------------------

``remaining-claim-preflight.json`` checks the declared source-row fingerprints,
claim/source/reference bindings and actual successful test receipts available
in each remaining candidate version. It is a read-only diagnostic matrix,
grants zero scope credit and is not substituted for semantic acceptance.
Its inputs are hashed and must remain unchanged while it runs.

The next audits must handle the body-operation collections' separate schema,
including mandatory controls plus appearance/result contexts. They must also
resolve incomplete historical reference bindings, missing unattended witnesses
and finite-list headings whose full child obligations are not established.
For example, strong newer orbit/epoch results do not authorize deleting the
inherited Workflow claim that their saved mapping still requires. Such missing
bindings remain explicit until a complete admissible witness is established;
a source-list/schema mismatch alone is not a production failure or an audited
semantic rejection.

The eighteen earlier substantive gaps remain as previously documented. No new
row was labelled complete merely because a diagnostic found some passing
components or because a later test name looked similar.
