Nested ephemeris dependency ownership
=====================================

Function value graphs now admit private EphemerisFile dependencies through their existing native spacecraft/frame/dynamics/wrapper binder. Context-owned ephemerides use a weak back-reference to the enclosing graph instead of an owning alias that would create a cycle. The GmatBase context registry resolves weak references and preserves that ownership role for same-graph assignment; fresh native copies acquire ordinary leases. Owning-source findings and implementation
------------------------------------------

The original BindCopy ephemeris branch rejected every non-public root. Simply removing that check would make the context own a private ephemeris that in turn owns the same context through functionCoordinateSystemOwners. The private ephemeris now passes the native binding path with an explicit empty frame-owner lease and a weak base-context registration. Public ephemeris roots retain their existing owning alias. Resolving a visited ephemeris returns its already-registered stable identity, as for other non-evaluating resource back-references.

GmatBase stores weak context entries in the existing external registry, leaving native class layouts and virtual contracts unchanged. Getter lookup locks that entry into a temporary owning lease. SetBorrowedFunctionValueContext stages its weak entry before retiring a previous strong lease; retirement remains outside the registry mutex. Ordinary clear/destruction removes both forms. Assigning another value from the same graph preserves an existing weak role, while a new destination has no weak registration and retains its incoming context normally.

EphemerisFile Clone now guards its cold native result with unique_ptr and invokes completed-root context rebinding. Copy keeps its previous context alive through assignment and reconnects only detached values; the existing active-trial writer-preservation branch remains. Context-owned ephemeris components also enter the native full binding path, including wrapper ownership registration. All three RetainFunction binding methods honor an explicitly empty owner lease so a nested value does not retain an obsolete graph alias.

Returned contexts record a non-owning public-root identity with its native weak lifetime token. Capturing an interior value includes the live root as a private dependency candidate, preventing a root back-reference from silently remaining an external borrow. An expired original root reports an explicit error before dereferencing it. Existing native owner/identity conflict guards continue to reject layouts the binder cannot represent. Ordinary graph construction suppresses completed-root hooks through the existing copy-depth scopes.

A vector now retains all imported ephemeris owner leases during graph construction instead of overwriting a single lease. After binding and native initialization complete, those source leases are released. Private copied subscribers remain dormant in the existing initialization policy; no file, output writer, accepted output history or active session is transferred. Native reporting-versus-value propagation policies, transient-force context, original type/domain checks and numerical methods remain.

Limits
------

This is dependency graph ownership and detached native binding, not complete function I/O/scoping or all-Resource cloning. Arbitrary changed owned component topology, duplicate owning identities, native owner-component conflicts, aliasing across incompatible public/embedded roots, external borrower lifetime and active solver/estimation/subscriber/MATLAB session restoration remain open. Interior detachment requires a live original public root during capture and retains explicit incompatibility errors; it does not resurrect an expired root or add shared ownership to a native component. Trial assignment still follows its existing live-writer preservation path. Direct raw C++ copy construction/operator assignment retains the existing staged native-copy contract; completed Clone/Copy and function-manager binding perform root reconnection. No runtime/lifetime/reload/numerical behavior has been verified. Matching rebuilt core/plugins are required for the added nonvirtual core method.
