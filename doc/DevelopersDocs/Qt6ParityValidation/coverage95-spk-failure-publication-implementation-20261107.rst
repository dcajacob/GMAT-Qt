Owning-source findings and implementation
------------------------------------------

Both SpiceOrbitKernelReader GetTargetState overloads intentionally represent a handled within-coverage SPICE gap with six -REAL_MAX values. They previously performed ICRF rotation or copied the failed native state array before replacing the result with that marker. The failed path now returns the same marker directly after existing error storage/range handling. CSPICE output arrays are value-initialized for deterministic diagnostics. Successful frame conversion and outside-coverage error/warning policies remain; the separate rotation-matrix methods are unchanged.

SPKPropagator ReadKernelState previously applied selected-origin subtraction to the reader result without distinguishing a gap marker from a state. A common local validator rejects missing/nonfinite data before translation, validates the origin and J2000-body states separately so two missing values cannot cancel, and validates the translated result before return. Valid state and origin arithmetic is otherwise unchanged. Existing translation errors remain native PropagatorExceptions.

Precision/Real Step and precision UpdateState had three inner generic BaseException handlers that suppressed lookup failures and then copied a default Rvector6 as a computed state. Those inner handlers are removed while native outer reporting/rethrow and caller-controlled skip handling remain. Both Step range-skip paths return false before copying state or invoking UpdateSpaceObject and set stepTaken to zero. Step without a kernel reader returns false. Void refresh cannot represent false success, so missing reader/out-of-span data reports a PropagatorException before a manager vector can be published.

RunPastStartEnd is a native measurement preparation mode used with CheckEpochValidity and coverage spans to omit unavailable measurements. SPK Initialize now checks its existing IsValidEpoch span policy when that mode is selected and guards both the lookup and state/publication with setState. An uncovered initial epoch can finish setup without replacing the spacecraft state with an invented zero sample. Default strict preparation still performs and validates the kernel query. The supported one-spacecraft restriction and lack of SPK STM/orbit-Jacobian support remain in their existing source and guide.

The source capture stopped before copying files because an ICRF reference path was wrong; the unfinished capture resumed with the actual coordsystem path before any source edits. The edit preflight was then restricted to the two target-state overloads so rotation-matrix-local failure variables were not modified. Source preimages, references and planning snapshots remain retained; no capture/final publication was replayed after mutation.

Limits
------

It does not make arbitrary provider/session failures atomic, roll back every attempted clock or kernel-global/cache mutation, add a new public result/status API, resurrect missing files or change measurement editing/scientific domains. Optional uncovered preparation leaves the spacecraft unchanged; its internal cache is not a covered ephemeris sample until a valid lookup completes. Native measurement validity checks and caller-controlled exception skipping still own whether an epoch is omitted.
