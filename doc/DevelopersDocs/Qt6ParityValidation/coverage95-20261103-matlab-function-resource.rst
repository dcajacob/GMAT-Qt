Failures and exact repairs
---------------------------

Three native failures remain authoritative failures: the first test left an
old ReportViewer open and hit the original ambiguous-viewer assertion; the
second reproduced stale MATLAB error state; the third emitted passing
functional proof but CTest timed out because detached MathWorks services held
its output pipe. No passed proof reclassifies the timeout.

The viewer correction explicitly closes the viewer after checking it. The core
repair in ``plugins/MatlabInterfacePlugin/src/base/interface/MatlabInterface.cpp``
uses a per-evaluation completion scalar rather than interpreting stale errormsg
as a new failure. A separate initialization prevents an unparsed syntax error
from reusing an earlier success. Scratch names mentioned in the issued
expression are avoided. Success no longer probes an absent errormsg through
GetString. The original native failure already contained the correct workspace
value 314160 while incorrectly reporting evaluation failure; that counterexample
and its exact source are retained.

This does not reserve a private workspace namespace or prove arbitrary
preexisting variable collisions, dynamic eval names, general exception domains
or exact original syntax diagnostics. The bounded syntax-error test intentionally
produces Unexpected ';', illegal catch and illegal end diagnostics. Those are
expected negative-input output; no blanket error-free MATLAB log is claimed.
The inherited diagnostic function-name extension formatting is also not fixed.

The opt-in ``GMAT_QT_CAPTURE_CHILD_OUTPUT=1`` launcher path captures native child
stdout/stderr in a temporary regular file and forwards it after the actual
child exits. It preserves the child exit code and full native output without
waiting for unrelated detached SDK services to close a CTest output pipe. It
does not kill licensing services or relax timeouts. Existing registrations retain
the original default launcher behavior.

Direct test linkage initially pulled MATLAB C++/MEX runtime dependencies and
shadowed system Qt with SDK Qt6DBus, causing two preserved link failures. The
plugin now links its actual Engine/Matrix/MAT C API dependencies privately.
No permissive unresolved-symbol linker option or SDK alias was added. The final
plugin's direct dependencies include libeng, libmx and libmat; no wx, MEX,
C++ Engine or Data Array runtime is a direct dependency. Two SDK boost indirect
link-search warnings remain in the final link log; the real executed plugin and
SDK image mappings are bound in both modes. Runtime compatibility outside these
selected calls remains unqualified.

Two later functional invocations lacked the independent observer trace because
the target was declared after the global observer enumeration. They are retained
as incomplete visibility evidence. The final target explicitly links the shared
observer object; only that affected case was rerun in both modes. Final runs are
``headless-v5`` and ``visible-v2``, using source capsule v6. Build-v8 passes.
The earlier target-selection build failure, missing-source metadata attempt,
failed offline audit for a missing input manifest, and suffix-assumption audit

name without a .so suffix; the corrected audit accepts that exact platform
